## 4. Key Decisions & Rationale

- **v3 copy was scrapped wholesale** — every headline described the landing page's mechanic
  ("Scroll, and this page prints itself line by line"). Zaid: "These are selling the Landing
  page not storeHub." v4 rule: headline = merchant outcome; the LP mechanic survives only in
  the CTA verb and the V2 artifact art, which preserves click-promise message-match.
- **LP-DAY reframed twice.** v4 first said "Open at 7am, closed at 11pm, and the day's numbers
  are already done." Zaid: a 16-hour day is not a value prop, it "sounds terrible." Final angle
  = live visibility away from the counter (Reporting & Analytics), not hours worked.
- **CTA labels stay campaign-locked** to each LP's verb (RUN THE COUNTER / GET YOUR NUMBER /
  SCROLL THE DAY / WATCH IT PRINT) — the ad must promise what the page does.
- **Shortened two headlines for rendering.** Nano Banana Pro drops or duplicates words on long
  headlines; shorter lines rendered exactly. Copy fidelity beat wording precision.
- **"e-Invoicing compliant" → "E-Invoice ready"** — the linter enforces the official feature
  name capitalisation "E-Invoice"; the checklist phrase "e-Invoicing compliant" is the only
  lowercase form allowed.
- **Model choice:** `nano_banana_pro` at 9:16 / 2k, 2 credits per image — best in-image text
  rendering of the available models, and cheap enough to iterate freely.

## 6. Gotchas & Dead Ends

- Higgsfield returned status **`nsfw`** (false positive, no output) for two jobs that used
  `renders/LP-CALC.A1.V1.png` (female subject) as the image reference. Using the receipt
  reference instead worked. If a job fails, check `"status"` in its JSON — the CLI's `--json`
  output is not valid single-document JSON, so grep for `"result_url"` / `"status"` rather
  than parsing it.
- Do **not** put percentage-based layout instructions in the prompt ("headline starts at 42
  percent") — the model rendered the literal strings "42%", "57%", "16%" onto the frame.
  Describing placement in words, plus a good reference image, works.
- The model wrote `$66.30` on a rendered POS screen. Must explicitly say currency is Malaysian
  ringgit written as RM, never a dollar sign.
- One render came back with a small Gemini sparkle watermark bottom-right; regenerating cleared
  it. Always eyeball each frame.
- Downloading the URL found by a naive regex grabs the *uploaded reference image*, not the
  output. Take the last `"result_url"` in the JSON.
- Receipt/POS line items in the renders are decorative gibberish at small size — acceptable at
  ad scale but re-check if any frame is ever shown large.
